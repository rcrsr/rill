# rill anti-patterns

Wrong/Right pairs aimed at TypeScript and Python reflexes. Load when generating fresh code.

## Assignment

    Wrong: x = 5
    Right: 5 => $x

    Wrong: let user = "alice"
    Right: "alice" => $user

    Wrong: const PI = 3.14
    Right: 3.14 => $pi

## Variable references

    Wrong: x.upper
    Right: $x -> .upper

    Wrong: print(name)
    Right: log($name)            # or $name -> log

## Curly braces (dict literals)

In rill, `{ ... }` is a block (function body, loop body, etc.), not a dict literal. Dicts use `dict[...]`.

    Wrong: {name: "alice"}
    Right: dict[name: "alice"]

    Wrong: {}                                  # empty block, not an empty dict
    Right: dict[]

    Wrong: {name: "alice", age: 30}
    Right: dict[name: "alice", age: 30]

    Wrong: {user: {name: "alice"}}
    Right: dict[user: dict[name: "alice"]]

    Wrong: list[{a: 1}, {a: 2}]
    Right: list[dict[a: 1], dict[a: 2]]

    Wrong: dict[user-id: 1]                    # bare identifiers must be snake_case
    Right: dict["user-id": 1]                  # quote the key for non-identifier names

## Truthy conditions

    Wrong: $name ? "have name" ! "no name"
    Right: $name -> .empty ? "no name" ! "have name"

    Wrong: $count ? "some" ! "none"
    Right: ($count > 0) ? "some" ! "none"

    Wrong: $list ? "items" ! "empty"
    Right: $list -> .empty ? "empty" ! "items"

    Wrong: !$value
    Right: $value -> .empty       # for strings/lists/dicts
    Right: ($value == 0)          # for numbers
    Right: !$bool                 # only on actual booleans

## Comparing mixed types

    Wrong: $n == "5"                       # halts: #TYPE_MISMATCH, types do not overlap
    Right: $n == 5

    Wrong: list[1, "a"] -> seq({ $ == "a" })   # halts on 1: elements carry their own type
    Right: list[1, "a"] => $l:list(union(number, string))
           $l -> seq({ $ == "a" })             # list[false, true]

    Wrong: list[dict[a: 1], dict[b: 2]] -> seq({ $ == dict[a: 1] })   # halts on element 2: dict shapes differ
    Right: list[dict[a: 1], dict[b: 2]] => $l:list(dict)
           $l -> seq({ $ == dict[a: 1] })      # list[true, false]

    Wrong: $r.!code == #MY_ERROR           # halts #TYPE_MISMATCH: not in the core error set
    Right: $r.!code == #NOT_FOUND

## Pipe targets

    Wrong: 3 -> list[$, $]                 # RILL-P030: literal target cannot read $
    Right: 3 -> { list[$, $] }

    Wrong: $x -> "label"                   # RILL-P031: string target ignores the value
    Right: $x -> "label {$}"

    Wrong: 42 -> $zero                     # RILL-R045: zero-parameter function gets an argument
    Right: $zero()

## Conversion versus assertion

    Wrong: $data -> dict(name: string)     # converts and fills, does not validate
    Right: $data -> :dict(name: string)    # asserts the shape

    Wrong: dict[a: 1, b: 2] -> :dict(a: number)   # halts #TYPE_MISMATCH: extra key
    Right: dict[a: 1, b: 2] -> dict(a: number)

    Wrong: "5" -> union(number, bool)      # halts RILL-R036: not a member
    Right: "5" -> number

## Loops

    Wrong: for item in list { ... }
    Right: $list -> seq({ ... })           # sequential, returns all results
    Right: $list -> fan({ ... })           # parallel, returns all results

    Wrong: for (let i = 0; i < n; i++) { ... }
    Right: range(0, $n) -> seq({ ... })

    Wrong: let total = 0
           for x in list { total += x }
    Right: $list -> fold(0, { $@ + $ })    # 6 for list[1,2,3]

    Wrong: while (x < 10) { x = x + 1 }
    Right: 0 -> while ($ < 10) do { $ + 1 }

## Code blocks are not values

A braced body runs where it is written. To store a function, put `fn` in front.

    Wrong: { $ * 2 } => $f                 # runs now: reads an unbound $ and halts RILL-R005
    Right: fn { $ * 2 } => $f
           4 -> $f                         # 8

    Wrong: { 5 } => $f                     # $f is 5, not a function
           $f()
    Right: fn { 5 } => $f
           $f()                            # 5

## Block argument arity

A block argument is typed by what it reads. Operators call with exact arity.

    Wrong: list[1, 2, 3] -> fold(0, { $ * 2 })   # halts RILL-R045: fold passes element and accumulator
    Right: list[1, 2, 3] -> fold(0, { $@ + $ })  # 6

    Wrong: list[1, 2, 3] -> seq({ 5 })           # halts RILL-R045: the block reads nothing, seq passes one
    Right: list[1, 2, 3] -> seq({ 5 + $ })       # list[6, 7, 8]

    Wrong: list[1, 2, 3] -> seq({ $@ })          # halts RILL-R044: $@ asks for a second argument
    Right: list[1, 2, 3] -> seq({ $ })           # list[1, 2, 3]

    Wrong: range(1, 5) -> start_when({ true })   # halts RILL-R045: start_when passes one argument
    Right: range(1, 5) -> start_when({ $ > 1 })  # stream from 2 onward; stop_when, iterate, chain take one argument too

## Held blocks in collections

A block written as a dict value or list element is held uncalled. Reads that select no entry halt.

    Wrong: dict[a: { $ + 1 }] -> seq({ $.key })  # halts #TYPE_MISMATCH: entry 'a' holds a code block
    Right: dict[a: fn { $ + 1 }] -> seq({ $.key })   # list["a"]; an fn entry is a value

    Wrong: dict[a: { $ + 1 }] -> .values          # halts #TYPE_MISMATCH
    Right: "a" -> dict[a: { "got {$}" }]          # "got a"; selecting the entry runs it with $ = "a"

## Reassignment inside loops

    Wrong: 0 => $sum
           $items -> seq({ $sum + $.price => $sum })   # halts: outer var reassigned

    Right: $items -> fold(0, { $@ + $.price })          # 0 + p1 + p2 + ...
    Right: $items -> acc(0, { $@ + $.price })           # list of running totals

## Collection locks

A variable locks to the full type of its first value, element types included.

    Wrong: list[1] => $x
           list["a"] => $x                  # halts RILL-R001: locked as list(number)
    Right: list[1] => $x:list(union(number, string))
           list["a"] => $x                  # list["a"]

## Try/catch

    Wrong: try { fetch(url) } catch (e) { fallback }
    Right: retry<limit: 3> { $app.fetch($url) } => $r
           $r ?? "fallback"

    Wrong: try { JSON.parse(s) } catch { null }
    Right: guard { $app.parse_json($s) } => $out   # JSON parsing is host-provided; rill has no built-in parser
           $out.! ? "parse failed" ! $out

## Null and undefined

    Wrong: x === null
    Right: $x.!                            # is this an invalid value?
    Right: $x -> .empty                    # is this an empty container?

    Wrong: x ?? default                    # JS nullish coalescing
    Right: $x ?? "default"                 # rill: vacant (empty OR invalid) coalescing

    Wrong: dict[a: undefined]
    Right: dict[a: ""]                     # explicit empty

## String operations

    Wrong: "Hello " + name
    Right: "Hello {$name}"                 # interpolation

    Wrong: name.toUpperCase()
    Right: $name -> .upper

    Wrong: arr.length
    Right: $arr.len                        # property, not method call

## Array methods

    Wrong: arr.map(x => x * 2)
    Right: $arr -> fan({ $ * 2 })          # parallel
    Right: $arr -> seq({ $ * 2 })          # sequential

    Wrong: arr.filter(x => x > 0)
    Right: $arr -> filter({ $ > 0 })

    Wrong: arr.reduce((acc, x) => acc + x, 0)
    Right: $arr -> fold(0, { $@ + $ })

    Wrong: arr.sort()
    Right: $arr -> sort                     # stable ascending
    Right: $arr -> sort -> .reverse         # descending
    Right: $arr -> sort({ $.score })        # sort by extracted key
    Right: $arr -> sort({ tuple[$.a, $.b] })  # multi-key

    Wrong: arr[arr.length - 1]
    Right: $arr[-1]                        # negative index from end

## Object access

    Wrong: obj.missing                     # undefined or error
    Right: $obj.missing ?? "default"       # vacant fallback
    Right: $obj.?missing                   # boolean: does field exist?

    Wrong: obj["computed-" + key]
    Right: $obj["{$prefix}-{$key}"]        # computed key

## Function literals

The `|params| body` literal is removed (RILL-P012 names the fn form). The body of `fn` is always a block on the same line.

    Wrong: |x| ($x * 2) => $double         # RILL-P012
    Right: fn(x) { $x * 2 } => $double

    Wrong: || { "hi" } => $hi              # RILL-P012
    Right: fn() { "hi" } => $hi

    Wrong: fn(x) ($x * 2) => $double       # paren or bare body; the body must be a block
    Right: fn(x) { $x * 2 } => $double

    Wrong: fn double(x) { $x * 2 }         # no named declaration form
    Right: fn(x) { $x * 2 } => $double

    Wrong: fn() { $ + 1 } => $inc          # RILL-P029: fn() takes no params, so it cannot read $
    Right: fn { $ + 1 } => $inc

    Wrong: fn(number = 1) { $ } => $f      # RILL-P028: an unnamed param carries no default
    Right: fn(n: number = 1) { $n } => $f

    Wrong: fn(x: number, string) { $x } => $f   # RILL-P028: named and unnamed params do not mix
    Right: fn(x: number, y: string) { $x } => $f

    Wrong: fn(x = "d") { $x } => $f        # a default does not infer the type; x is any
    Right: fn(x: string = "d") { $x } => $f

## Function types

`fn` is the type of every function. `closure` in a type position is removed (RILL-P012 names fn).

    Wrong: $f -> :closure                  # RILL-P012
    Right: $f -> :fn

    Wrong: $f -> :|x: string|:string       # RILL-P012
    Right: $f -> :fn(x: string):string

    Wrong: $fns -> :list(closure)          # RILL-P012
    Right: $fns -> :list(fn(x: string):bool)

    Wrong: $f -> :fn(x: number)            # exact: a function with a default or a different outer does not match
    Right: $f -> :fn(x: number = 0):any

## Function calls vs script functions

    Wrong: $double(5)                      # if $double is a built-in or host fn
    Right: double(5)                       # no $ for built-in/host calls

    Wrong: log($x)                         # if log was assigned to $log
    Right: $log($x)                        # script functions need $

    Wrong: fn(x) { $x * 2 } => double      # capture name needs $
    Right: fn(x) { $x * 2 } => $double

    Wrong: app::fetch($url)                # removed namespaced call (RILL-P012)
    Right: use<ext:app> => $app
           $app.fetch($url)

## Callable reflection

    Wrong: $fn.^input                      # removed; halts naming the replacement
    Right: $fn.^type.inner                 # ordered[x: number]

## Union types

    Wrong: 42 -> :string|number
    Right: 42 -> :union(string, number)

    Wrong: "c" => $unit:"c"|"f"            # TypeScript literal union
    Right: "c" => $unit:union("c", "f")

## Comments

`#` followed by a letter or `_` is an atom, not a comment. A comment needs a space after `#`.

    Wrong: $list -> .len #count
    Right: $list -> .len  # count

    Wrong: #TODO fix this later
    Right: # TODO: fix this later

## Whitespace traps

Only the first halts. The rest parse and run; the checker reports them at
info level. Write them tight anyway.

    list [1, 2, 3]    # ERROR (RILL-P007): keyword and bracket must be adjacent
    $obj. field       # SPACING_MEMBER: dot must touch the field name
    $obj .field       # SPACING_MEMBER: same, on the other side
    $x->.upper        # SPACING_OPERATOR: pipe needs spaces both sides
