# rill types

Type names, assertions, conversion, parameterized types, dict shapes, type inspection.

## Type names

    string   number   bool     list     dict     ordered
    tuple    closure  vector   iterator any      type
    atom     datetime duration    error_code

## Type assertion `:type`

Halts with `#TYPE_MISMATCH` if value does not match.

    42:number                       # passes
    "x":number                      # halts
    $val:list(string)               # parameterized
    $val -> :number                 # pipe form

## Type check `:?type`

Returns boolean. Never halts.

    42:?number                      # true
    "x":?number                     # false
    $val -> :?number                # pipe form

## Union types

    42 -> :union(string, number)    # passes
    #TIMEOUT -> :error_code         # passes
    #ok -> :error_code              # halts #TYPE_MISMATCH
    42:?union(string, number)       # true
    "hello" => $x:union(string, number)   # capture with union

Members may be scalar literals (string, number, bool, atom).

    "c" -> :union("c", "f")         # passes
    "x" -> :union("c", "f")         # halts #TYPE_MISMATCH
    union(#wired, #wireless) => $lan   # union type in a variable

A declared set is closed. A value outside it halts; an undeclared value never does.

    "c" => $kind:union("c", "f")
    $kind == "c"                    # true
    $kind == "f"                    # false
    $kind == "x"                    # halts #TYPE_MISMATCH: "x" is outside the set
    "x" == "c"                      # false: neither side is declared

`|` is not a type separator, and a bare literal after `:` is a parse error. Write `union("c")`.

## Parameterized constructors

Structural types with field/element constraints.

    list(string)                    # list of strings
    dict(name: string, age: number) # dict with these fields
    dict("a b": number)             # quote a key that is not an identifier
    tuple(number, string)           # positional tuple
    tuple(number)                   # exactly one number; any length is list(number)
    ordered(x: number, y: number)   # named ordered args
    list()                          # empty parens mean unspecified: same as list(any)

An outer type (`:string` after the parentheses or a bare name) attaches only to `stream`: `stream:number` is `stream(any):number`. `list(number):string` and `list:string` halt `RILL-P006`.

## Asserting dict shapes

    $data -> :dict(name: string, age: number)
    $data:?dict(name: string, age: number)

Assertion is exact: an extra key halts #TYPE_MISMATCH (`:?` gives false). Bare `dict` and `dict()` accept any keys.

In closure params (validates input structure):

    |d: dict(name: string, age: number)| {
      "{$d.name} is {$d.age}"
    } => $format_person

## Property access with type guards

    $data.field                     # dict field
    $data[0], $data[-1]             # list index (negative from end)
    tuple[1,"a"][1]  # "a" — tuple and ordered index by position; ordered also by key
    $data.$key                      # variable as key
    $data[$i + 1]                   # computed key
    $data[1]                        # halts #TYPE_MISMATCH on a dict: keys are strings; use $data["1"]
    $data.field ?? "default"        # vacant fallback
    $data.?field                    # boolean: does field exist?
    $data.?field&string             # exists AND is string
    $data.?$key&number              # variable existence + type check
    $data.?[$expr]&list             # computed existence + type check
    $data.?[5]                      # absent key or out-of-range index is false; a wrong-typed selector halts like $data[5]

The 8 dict method names are reserved and cannot be used as dict keys:

    len   first   empty   eq   ne   keys   values   entries

    dict[len: "fake"]                # halts: reserved method name 'len'
    dict[label: "fake"].len          # fine: dict length (non-reserved key)

`.keys`/`.values`/`.entries` and dict iteration visit dict's canonical order (see the Types reference for the exact rule). On a non-dict receiver these three methods halt (`RILL-R003`) instead of returning an empty list.

## Tuple lexicographic comparison

Tuples support `<`, `>`, `<=`, `>=`, `==`, `!=`. Comparison walks elements left to right; the first differing position decides. Each element compares using its own type's protocol. Empty `tuple[]` equals `tuple[]`.

    tuple[1, 2] < tuple[1, 3]              # true
    tuple[2, 1] > tuple[1, 9]              # true
    tuple[1, 2] == tuple[1, 2]             # true

Index a tuple with `[i]` or `.at(i)`; negative indexes count from the end; `.1` is a parse error.

Dicts have NO comparison protocol. Use tuples for multi-key ordering, including with `sort({ tuple[$.a, $.b] })`.

**Errors:** different-length tuples or differently-typed corresponding elements halt with `#TYPE_MISMATCH`.

## Type conversion `-> type`

Explicit conversion between compatible types. Halts with `RILL-R036` on invalid pairs.

    42 -> string                    # "42"
    "3.14" -> number                # 3.14
    list[1, 2] -> tuple             # tuple[1, 2]
    tuple[1, 2] -> list             # list[1, 2]
    ordered[a: 1] -> dict           # dict[a: 1]

A parameterized target converts each element or field. A failing part halts `RILL-R038` or `RILL-R036` and names the part.

    list[1, 2] -> list(string)      # list["1", "2"]
    list["1", "x"] -> list(number)  # halts RILL-R038 naming element 1
    dict[a: 1] -> dict(a: string)   # dict[a: "1"]
    list[1, 2] -> :list(string)     # halts #TYPE_MISMATCH: `:` checks, never converts

    "5" -> union(number, string)    # "5": a member passes unchanged, declared as the union
    "5" -> union(number, bool)      # halts RILL-R036: not a member, members are never tried in turn

To validate a shape write `-> :dict(a: string)`, never `-> dict(a: string)`. To drop extra keys, convert first: `dict[a: 1, b: 2] -> dict(a: number)` is `dict[a: 1]`.

### Conversion matrix

    Source   | -> list | -> dict | -> tuple | -> ordered(sig) | -> number | -> string | -> bool
    ---------|---------|---------|----------|-----------------|-----------|-----------|--------
    list     | no-op   | error   | valid    | error           | error     | valid¹    | error
    dict     | error   | no-op   | error    | valid           | error     | valid¹    | error
    tuple    | valid   | error   | no-op    | error           | error     | valid¹    | error
    ordered  | error   | valid   | error    | no-op           | error     | valid¹    | error
    string   | error   | error   | error    | error           | valid²    | no-op     | valid³
    number   | error   | error   | error    | error           | no-op     | valid¹    | valid⁵
    bool     | error   | error   | error    | error           | valid⁴    | valid¹    | no-op

    ¹ formatValue semantics
    ² parseable strings only; halts with RILL-R038 on failure
    ³ accepts only "true" and "false"; halts with RILL-R036 otherwise
    ⁴ true → 1, false → 0
    ⁵ 0 → false, 1 → true; all other values halt with RILL-R036

    closure, iterator, and vector have no -> string, nor does a list, dict, tuple, or ordered holding one at any depth; converting, interpolating, or .join-ing one halts RILL-R036
    datetime and duration interpolate as their printed form, and duration -> string yields it; -> string on a datetime, or on a collection holding a datetime or duration, halts RILL-R036

## Default values in type constructors

    dict(a: string, b: string = "x")
    ordered(x: number, y: number = 0)
    tuple(string, number = 0)

    dict[b: "b"] -> dict(b: string, a: string = "a")   # dict[a: "a", b: "b"]

Only `-> type` conversion fills defaults. `:` assertion does NOT hydrate defaults. Nested fields recurse.
Under a union, the narrowest matching member fills defaults, whatever the written order.

## Datetime and duration

Constructed with function-call syntax.

    datetime("2024-01-15T00:00:00Z") -> .year         # 2024
    datetime(...dict[year: 2024, month: 1, day: 15])  # named components via spread
    now()                                              # current datetime
    duration("25h") -> .days                          # 1
    duration("1y") -> .months                         # 12
    "1h30m" -> duration                               # duration("1h30m"); halts INVALID_INPUT if malformed
    duration("90s") -> string                         # "1m30s", the printed form
    # printed form: units in order y mo d h m s ms, each at most once; only ms may be decimal
    # (1s500.5ms); each component at most 2^53-1

## Type inspection `^type`

Returns a type value for runtime inspection.

    42.^type                        # type value for number
    42.^type.name                   # "number"
    list[1, 2].^type.name           # "list"
    list[1, 2].^type.signature      # "list(number)"
    list[1, "a"].^type.signature    # "list(union(number, string))"

A mixed list is legal and infers `list(union(...))` over the element types whatever their order. A declared element type such as `:list(number)` rejects it with `#TYPE_MISMATCH`. An element read from an undeclared list carries its own type, so declare `:list(union(number, string))` to compare elements across types.

Read what a type holds with `.inner` and what a function or stream yields with `.outer`:

    list(number).inner              # number
    dict(a: number).inner           # dict[a: number]
    tuple(string).inner             # tuple[string]
    union("b", "a").inner           # list["a", "b"] (canonical order)
    union(1, "a").inner => $u
    $u.^type.signature              # "list(union(number, string))"
    string.inner ?? any             # any; leaf types halt RILL-R003 without ??
    string.?inner                   # false
    |x: number|{ $x }:string => $f
    $f.^type.outer                  # string
    dict(a: string = "x").defaults  # dict[a: "x"]

Under a declared union, `.^type` reports the declaration and `.^effective` the own type:

    42 => $x:union(string, number)
    $x.^type.name                   # "union"
    $x.^effective.name              # "number"

Dispatch on `.^effective.name`, not `.^type.name`. `any` declares nothing:
`1 => $x:any` locks as number.

A declaration carries through `$`, plain and inline captures, grouped `( )`, `pass`, destructure, closure params, iteration over a declared `list(E)`, and every element or field read on a declared collection: `[i]`, `.name`, `.$k`, and pipe selection `"a" -> $d`. A capture locks to the carried declaration.
Computed results (operators, methods like `.head`, calls) take their own type.
A bare `list`, `list(any)`, or `union(list(number), string)` projects no element type. A bare kind such as `:list` makes `.^type` report `list` and `.^effective` report `list(number)`.
Host boundary: `toNative` reports the own type.
Migrate `$v.^type == number` to `$v.^effective == number` or `$v -> :?number` under a declared union.

Equality:

    $val.^type == list(number)      # true if $val is list(number) with no declaration (own type)
    $val.^type == $other.^type      # compare structural types
