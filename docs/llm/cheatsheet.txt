# rill cheatsheet

Default context for any rill task. Covers the 7 critical differences, syntax, `$` binding, and callable types. Read first.

## The 7 critical differences

### 1. No assignment operator

    Wrong: x = 5         Mainstream: x = value
    Right: 5 => $x       rill:       value => $x

`->` pipes a value to the next operation. `=>` captures a value AND continues the chain.

    "hello" => $x -> .upper => $y    # $x="hello", $y="HELLO"

### 2. No null or undefined

Empty values (`""`, `0`, `false`, `list[]`, `dict[]`) exist. "No value" cannot be represented.

    $dict.field ?? "default"          # default if vacant
    $str -> .empty ? "was empty"      # explicit check

### 3. No truthiness

Conditions must be boolean. No coercion. Negation also requires boolean.

    Wrong: "" ? "yes" ! "no"          Right: "" -> .empty ? "yes" ! "no"
    Wrong: 0 ? "yes" ! "no"           Right: (0 == 0) ? "yes" ! "no"
    Wrong: !"hello"                   Right: "hello" -> .empty -> (!$)

### 4. Variables lock to first type

    "hello" => $x
    42 => $x        # ERROR: cannot assign number to string variable

The lock is the declared type the value carries, else its own type: `1 => $x:union(number, string)` then `"a" => $x` is OK. `1 => $x:any` locks as number.

Without a declaration the lock is the full inferred type: `list[1] => $x` then `list["a"] => $x` halts RILL-R001. Annotate the wider type first: `list[1] => $x:list(union(number, string))`.

A dict lock is exact (`dict[a: 1] => $x` rejects `dict[a: 1, b: 2]`), a tuple lock is positional (`tuple[1] => $x` rejects `tuple[1, 2]`), and a function locks to its full signature (`fn(n: number) { $n } => $f` rejects `fn(s: string) { $s }`), each halting RILL-R001.

### 5. No variable shadowing

Child scopes can READ parent variables but cannot WRITE or redeclare. Loop bodies cannot mutate outer state.

    Wrong: 0 => $count
           list[1, 2, 3] -> seq({ $count + 1 => $count })   # runtime error

    Right: list[1, 2, 3] -> fold(0, { $@ + $ })             # 6

`for` does not exist. Use `seq`, `fan`, `fold`, `acc`, `filter`, `sort`, or `while`.

### 6. Errors halt — recover with `guard`

No try/catch. Failures throw runtime errors (uncatchable) or produce **invalid values** that halt on access. Recover access halts with `guard { }` or `retry<limit: N> { }`. Inspect with `.!`, `.!code`, `.!message`.

### 7. Value semantics

All copies are deep. All comparisons are by value. No object identity.

    list[1, 2, 3] == list[1, 2, 3]   # true
    list[1, 2] => $a
    $a => $b                          # $b is an independent deep copy

`==` and `!=` halt with `#TYPE_MISMATCH` when the operand types cannot overlap, as in `1 == "1"`. Overlapping types of different kinds compare unequal.

## Syntax quick reference

    Variables:    $name (always prefixed with $)
    Strings:      "hello {$var}"        # interpolation with {}
                  """multiline"""        # also interpolates
    Numbers:      42, 3.14, -7
    Booleans:     true, false
    Atoms:        #TIMEOUT              # named symbols (case-sensitive)
    Lists:        list[1, 2, 3]
                  list[...$xs, 4]       # spread
    Dicts:        dict[name: "alice", age: 30]
                  dict[1: "one", 2: "two"]  # number keys name the strings "1", "2" (incl. "-1")
                  dict[true: "yes", false: "no"]  # boolean keys name "true", "false"
                  dict[list["a", "b"]: 1]  # multi-key: dict[a: 1, b: 1]; a repeated key is RILL-P027
                  dict[$keyVar: value]  # variable key (dict/ordered: must eval to string)
                  dict[("{$a}{$b}"): value]  # computed key (dict/ordered: must eval to string)
    Tuples:       tuple[1, 2, 3]
    Ordered:      ordered[a: 1, b: 2]   # named-arg unpacking
    Functions:    fn(x) { $x + 1 }      # explicit
                  fn { $ + 1 }          # unnamed param from the reads
                  { $ + 1 }             # code block: runs where written, never a value
    Type annot:   "hi" => $x:string
    Modules:      use<module:greet> => $g
    Extensions:   use<ext:llm> => $llm
    Comments:     # single line only; a space after # is required (#word is an atom)
    Frontmatter:  ---\nkey: value\n---  # YAML at top of script

A written type before a literal on the same line declares it: `list(number)[1, 2]`, `union("a", "b") "a" => $x`. The capture locks the declared type, and a value outside it halts #TYPE_MISMATCH. A newline ends the type: `list(number)` then `[1, 2]` on the next line is two statements.

`list [1]` equals `list[1]`: spaces or tabs before `[` are allowed on the same line. `use <ext:app>` still halts RILL-P007: `<` needs adjacency.

Atoms are identified and compared by name: #FOO == #BAR is false, and any well-formed name is an atom. Nothing is registered. See errors for the built-in atoms and the core error set.

## Pipes and `$` binding

`$` is the current piped value. Its meaning depends on context:

| Context | `$` contains |
|---|---|
| `-> { body }` | piped value |
| `-> seq({ })` / `fan({ })` / `filter({ })` | current item |
| `-> fold(i, { })` / `acc(i, { })` | current item (`$@` = accumulator) |
| `while (cond) do { }` | accumulated value |
| `cond ? a ! b` | pipe value entering the conditional (either branch) |

Implied `$`: bare `.method` means `$ -> .method`. `"hello" -> .upper` is `"hello" -> $.upper`.

**Pipe binding when `->` targets a callable.** If no top-level `$` appears in the argument list, the piped value is auto-prepended. If any top-level `$` appears, every `$` resolves to the piped value (no auto-prepend). Block arguments (`{ ... }`) hide their inner `$` from the scan. See `callables` for the full table.

    $list -> filter({ $.active })       # filter($list, { ... }); block argument $ is read per element
    [1,2,3] -> fold(0, { $@ + $ })      # fold([1,2,3], 0, ...) — list auto-prepended
    10 -> $fmt(1, $, 0)                 # $fmt(1, 10, 0) — explicit placement

Always prefer implicit `$`:

    .method        # over $.method
    func           # over func($)
    $fn            # over $fn($)

Don't capture just to continue a chain. Use line continuation. Capture only when reused.

## Callable types

| Type | Source | Examples |
|---|---|---|
| Function | Script-defined | `fn(x) { $x * 2 }`, `fn { $ + 1 }` |
| Built-in | Shipped with runtime | `log`, `json`, `range`, `repeat`, `chain` |
| Host | Registered by host | `$app.fetch()` (hoisted via `use<ext:app> => $app`) |

The `$` prefix disambiguates:

    name()    -> built-in or host call
    $name()   -> function invocation
    $name     -> variable reference
    name      -> dict key literal

## Operator precedence (highest to lowest)

1. Member access: `.field`, `[index]`
2. Type operators: `:type`, `:?type`
3. Unary: `-`, `!`
4. `*` `/` `%`
5. `+` `-`
6. Comparison: `==` `!=` `<` `>` `<=` `>=`
7. `&&`
8. `||`
9. `??`
10. `->`
11. `=>`

Use parentheses to override.

## Collection operators

| Operator | Signature | Semantics |
|---|---|---|
| `seq` | `seq(list, fn)` | Transform each item sequentially; returns all body results |
| `fan` | `fan(list, fn)` | Transform each item in parallel; returns all body results |
| `filter` | `filter(list, fn)` | Keep items where body returns `true` |
| `fold` | `fold(list, init, fn)` | Reduce to single value; `$@` = accumulator |
| `acc` | `acc(list, init, fn)` | Like `fold` but emits accumulator at each step |
| `sort` | `sort(list, key_fn?)` | Stable ascending sort; dict and ordered input return `ordered`, tuple input returns `list`; iterators are materialized; over 10,000 elements halts `RILL-R010` (fatal) |
| `take` | `take(list, n: int) -> list[T]` | First n elements; `n < 0` halts `#INVALID_INPUT`; a result over 10,000 halts `RILL_R010` (catchable) |
| `skip` | `skip(list, n: int) -> list[T]` | Drop first n elements; `n < 0` halts `#INVALID_INPUT`; n past length → empty |
| `cycle` | `cycle(list) -> iterator[T]` | Repeat input indefinitely as iterator; empty input → empty; bound at consumer |
| `batch` | `batch(list, n: int, options?) -> stream[list[T]]` | Chunks of n; `drop_partial: true` discards trailing short chunk |
| `window` | `window(list, n: int, step: int = n) -> stream[list[T]]` | Sliding windows of n; default step=n (non-overlapping); `step > n` makes gaps |
| `start_when` | `start_when(list, predicate: fn) -> stream[T]` | Yield from first match onward; predicate must return `bool` |
| `stop_when` | `stop_when(list, predicate: fn) -> stream[T]` | Yield through first match (inclusive); predicate must return `bool` |
| `pass { body }` | `pass { body }` | Side-effect block; pipe value flows through unchanged; halts in body propagate |
| `pass<on_error: #IGNORE>` | `pass<on_error: #IGNORE> { body }` | Side-effect block; suppresses catchable halts in body; `on_error: #IGNORE` is the only valid option (else RILL-P004) |

## Script return values

| Return value | Exit code |
|---|---|
| `true` / non-empty string | 0 |
| `false` / empty string | 1 |
| `list[0, "message"]` | 0 with message |
| `list[1, "message"]` | 1 with message |
